# 密码学基础构件（二）：密码学随机数与 nonce

密钥、签名随机标量、协议挑战和加密 nonce 都可能涉及随机数，但它们对保密性、唯一性与不可预测性的要求并不相同。把这些值一律称作“随机数”，容易掩盖真正需要维持的条件。

密码学实现首先应明确每个值的职责，再选择生成方式。名字相同，不代表可以采用同一套复用和恢复规则。

## 一、随机源与伪随机生成器各自负责什么

物理或系统事件可以提供不确定性，密码学伪随机生成器再利用秘密状态产生较长输出。确定性随机比特生成器 DRBG 是正规的密码构造，安全目标不同于普通用途随机数生成器。

关键区别在于：种子和状态受到保护时，攻击者能否有效预测输出，而不是输出是否通过几个频数测试。足够复杂的统计图形，并不证明它适合生成密钥。

实际应用通常应使用操作系统或经过审查的密码库提供的随机接口，处理接口失败，并满足其初始化条件。时间戳、设备号和进程号可以变化，却通常不能独立提供足够的秘密熵。

随机源、提取处理和生成器还承担不同职责。对低质量输入做一次哈希，不会凭空创造攻击者未知的信息；相关熵估计必须分析来源与攻击者知识。

## 二、内部状态同样属于秘密

如果两台设备从同一个随机生成器状态启动，随后调用顺序又相同，就可能产生相同输出。虚拟机快照、备份恢复、进程复制和测试替身，都可能影响这一前提。

不同生成器对状态泄露后的历史输出保护和未来恢复能力有不同保证，不能把它们自动归给所有 CSPRNG。应用需要遵循具体库的重播种、分叉和生命周期要求。

对密钥生成而言，重复输出可能产生相同密钥；对签名而言，重复秘密随机标量可能直接泄露私钥。随机源失败因此常表现为安全边界崩溃，而不仅是“签名不够随机”。

## 三、nonce 是职责描述，不是统一数据类型

| 使用场景 | 典型要求 | 是否通常保密 |
| --- | --- | --- |
| AEAD nonce | 同一密钥下满足方案规定的唯一性等条件 | 通常不保密 |
| ECDSA 秘密随机标量 | 按规范生成，保密，避免跨不同消息违规复用 | 保密 |
| 认证挑战 | 通常需要新鲜性，某些场景还要求不可预测 | 通常可公开 |
| 业务请求序号 | 按协议排序或防重放，并由接收方检查 | 通常可公开 |

表中的要求仍以具体协议为准。有些方案提供 nonce 误用抵抗能力，有些方案却会在重复时严重失效。不能只看到字段名为 nonce，就忽略算法文档。

一个公开计数器可以用于满足某些加密方案的唯一性要求，却不能直接替代需要保密且不可预测的签名随机标量。

## 四、均匀采样不能随便取模

假设随机接口均匀输出 3 位整数，也就是 0 到 7。现在希望均匀选择 0 到 4，如果直接模 5，分布就会偏斜：

| 目标值 | 对应原始值个数 |
| --- | --- |
| 0、1、2 | 各有两个 |
| 3、4 | 各有一个 |

前三个值的概率是后两个值的两倍。这个小例子说明，均匀字节经过任意取模，不一定变成均匀标量。

一种办法是拒绝采样：只接受原始值 0 到 4，遇到 5、6、7 就重新抽取。接受后的五个值等概率；如果目标是 1 到 5，再将结果加一。

真实密码库也可能采用足够宽的输入后约减，使偏差达到指定安全界。实现时应采用具体算法规定的方法，不能把“有偏差”和“所有约减都不安全”混为一谈。

## 五、确定性签名解决了一部分随机源问题

RFC 6979 为 DSA/ECDSA 定义了由私钥与消息等材料确定性生成签名随机标量的方法。这样可以减少每次签名对外部高质量随机源的依赖，同时保持与常规验证者的兼容性。

但确定性不代表可以公开随机标量，也不代表允许自行更改派生过程。它仍依赖秘密密钥、中间状态与实现得到正确保护。

对同一消息产生同一签名，和对不同挑战复用同一秘密随机标量，是不同情况。更不能把单机签名规则直接搬到门限协议：其他参与者的消息、并发与重放，会带来新的攻击条件。

因此，门限签名必须遵循相应协议的 nonce 生成、承诺和使用规则，不能简单对“密钥份额加消息”做哈希就宣布完成确定性改造。

## 六、唯一性需要跨越失败和恢复

如果 AEAD 使用计数器生成 nonce，应当明确计数器属于哪个密钥和设备，何时递增，怎样持久化，以及恢复备份时如何避免倒退。

如果使用随机 nonce，应当评估同一密钥下的使用量、碰撞概率和随机源失效。多设备共享密钥时，还要考虑是否独立生成或协调命名空间。

重发旧密文与重新执行加密也要区分。网络重传可以重新发送原有数据包；若使用同一 nonce 加密不同内容，则可能违反安全前提。业务失败不能自动使一次已经暴露的随机材料重新变得可用。

日志应记录足够的状态依据，但不能为了排查问题把密钥、秘密随机标量或原始随机状态完整输出。
