# 现代密码学总览与知识体系

现代密码学围绕一个核心问题展开：在存在攻击者的环境中，如何保护信息、验证声明，并让互不完全信任的参与者完成协作。

加密、数字签名、密钥协商和安全多方计算，分别承担不同职责。学习这些技术，需要先建立它们之间的关系，再逐步进入数学、算法和实现细节。

对于钱包与签名系统，这条主线可以概括为：**明确安全目标，选择密码机制，设计交互协议，并在工程中持续维持其安全前提。**

## 一、先区分需要实现的安全目标

最基础的三个目标是机密性、完整性和认证。

**机密性**关注信息是否会被未获授权者获知。例如，密钥备份被复制后，复制者能否读出其中的秘密。

**完整性**关注未经授权的修改能否被发现。例如，接收地址或转账金额被改动后，系统能否识别。

**认证**关注消息来源或交互对象是否可信。其中，数据来源认证验证消息与某个密钥持有者的关系；实体认证则关注当前交互的对方身份。

在这些目标之外，密码学还研究隐私保护与可验证性，例如隐藏参与者的私有输入，或者证明某项计算符合约定规则。

这些能力有各自的边界。确认请求来自某个账户后，系统仍需判断它是否有权执行操作；验证交易签名通过后，仍需判断交易是否符合业务意图。**认证、授权与业务正确性，需要分别检查。**

## 二、基础技术分别解决什么问题

| 技术 | 主要职责 | 典型例子 |
| --- | --- | --- |
| 对称加密 | 使用共享秘密密钥保护数据内容 | AES 的适当工作模式、ChaCha20 |
| 公钥加密 | 使用接收方公钥加密，由相应私钥解密 | RSA-OAEP |
| 哈希 | 把消息映射为摘要，供比较、索引及其他密码构造使用 | SHA-256、SHA-3 |
| 消息认证码 MAC | 使用共享密钥认证消息 | HMAC |
| 数字签名 | 使用私钥签名，让公钥持有者验证 | ECDSA、Schnorr、EdDSA |
| 密钥协商 | 通过交互建立共享秘密 | DH、ECDH |
| 密钥封装 KEM | 生成共享秘密及相应封装数据，供接收方恢复秘密 | ML-KEM |
| 密钥派生 KDF | 将已有秘密材料加工为适合特定用途的密钥 | HKDF |
| 认证加密 AEAD | 同时保护明文机密性、完整性，并认证附加数据 | AES-GCM、ChaCha20-Poly1305 |

“非对称密码”是包含公钥加密、数字签名等机制的更广泛类别，不能简单理解为“非对称加密”。

几个容易混淆的关系尤其值得记住：

- **哈希通常不使用秘密密钥。** 如果攻击者能同时替换文件和摘要，单独计算哈希无法认证来源。
- **MAC 的验证方通常也能生成标签。** 因此，它与允许第三方公开验证的数字签名有不同的信任结构。
- **数字签名不隐藏消息。** 它提供完整性与基于公钥的认证依据；公钥属于谁，还需要可信的身份绑定机制。
- **密钥协商需要身份认证配合。** 裸 ECDH 可以建立共享秘密，但无法独自阻止中间人攻击。

数字签名的完整性、认证和证据用途，可以进一步参考 [FIPS 186-5](https://csrc.nist.gov/pubs/fips/186-5/final)。

实际系统通常组合使用这些机制。例如，混合加密先利用公钥机制建立秘密，再经过 KDF 派生密钥，最后使用 AEAD 保护业务数据。[HPKE](https://www.rfc-editor.org/rfc/rfc9180.html) 就将这类组合划分为 KEM、KDF 和 AEAD。

## 三、判断安全，需要先说明攻击条件

现代密码学的重要特征，是通过明确的定义、假设与分析论证安全。算法设计通常假定算法可以公开，核心秘密由密钥等敏感状态承担。

一句“没有私钥就无法破解”，没有充分描述安全条件。还需要回答：攻击者能否选择待加密的消息，能否请求解密，能否让系统签署自选消息，以及能否控制部分协议参与者。

例如，数字签名需要考虑：攻击者已经获得很多自选消息的合法签名后，能否进一步伪造新消息的签名。多方协议则需要说明：允许多少参与方被控制，被控制者只是观察数据，还是能够任意偏离协议。

安全结论还依赖相应假设。许多实用方案属于计算安全：攻击在数学上可能存在，但对计算资源受限的攻击者而言应当不可行。安全证明把方案与特定假设联系起来，其结论也受分析模型的约束。

因此，判断一个方案时，应当把下面三个问题放在一起：

1. 它保护什么性质？
2. 攻击者拥有多少能力？
3. 结论依赖哪些数学、协议与实现前提？

安全证明通常不会自动覆盖模型之外的日志泄露、错误授权或设备失陷。

## 四、ECC、MPC 与 HSM 位于不同层次

### 4.1 ECC 提供数学平台，签名方案规定具体规则

椭圆曲线密码学，简称 ECC，围绕椭圆曲线群构造密码机制。点运算、标量乘法、子群与点编码，是理解相关方案的公共基础。

ECDSA、Schnorr 和 EdDSA 是签名方案；ECDH 用于密钥协商。即使使用相关的曲线，它们也具有不同的算法规则。

因此，需要分清“使用哪条曲线”“执行什么算法”“按照什么规范编码”，不能用一个名称代替三层含义。

### 4.2 MPC 研究多方协作，门限签名是重要应用

安全多方计算，简称 MPC，研究多方如何在模型允许的泄露范围内，对私有输入进行联合计算，并满足相应的正确性要求。

门限签名关注一个更具体的问题：由达到门限数量的参与方共同完成签名，正常流程无需集中恢复完整私钥。

FROST、GG18、GG20、CMP、CGGMP 等属于需要分别研究的具体协议路线。它们的安全模型、交互方式和预处理能力，应当按照具体论文版本与实现进行分析。

协议中的“离线阶段”通常指提前执行的预处理；设备完全断网则是部署属性，二者不能直接等同。

### 4.3 HSM 保护执行环境，MPC 分散签名能力

硬件安全模块 HSM 提供受保护的密钥管理和密码运算环境，可以限制密钥导出与使用权限。它的实际保护能力取决于设备、配置和管理方式。

MPC 则可以把某项签名能力分散到多个参与方。两者可以组合，例如让多个参与方分别在受保护的硬件环境中使用各自份额。

分析时，需要分别检查硬件保护、参与方独立性、调用权限和业务授权。拥有其中一种机制，并不自动满足其他层面的要求。

零知识证明、同态加密和后量子密码，也各有研究目标：分别涉及证明时的信息泄露、密文上的计算，以及抵抗已知量子攻击的密码构造。它们是知识体系的延伸方向。

## 五、用一次钱包转账连接这些概念

假设某钱包收到一条转账指令：“向指定地址转出 10 个代币。”

这条指令到最终执行，涉及多个独立的安全环节：

1. **交易构造。** 把业务意图转换成特定网络中的待签名交易，明确资产、地址、金额、费用及必要的防重放字段。
2. **解析与授权。** 签名端解析交易，核对其与审批内容是否一致，并检查白名单、额度和权限。
3. **密钥使用与签名。** 按既定方式使用软件密钥、HSM 或门限协议，对确切的交易消息生成签名。
4. **通信与状态管理。** 认证交互方，保护需要保密的数据，并检查会话、消息顺序和重复请求。
5. **广播与确认。** 核对最终交易与已授权、已签署的内容一致，再广播并跟踪执行结果。

假如系统错误地批准了恶意接收地址，之后完全正确的签名仍会授权错误交易。假如系统没有记录已处理请求，一条合法指令也可能被重复执行。

AEAD 能提供认证加密，但防重放还需要协议状态与验证规则；[RFC 5116](https://www.rfc-editor.org/rfc/rfc5116.html) 明确将防重放和访问控制与 AEAD 接口本身区分开来。

这个例子说明：钱包安全需要把密码机制与交易语义、授权策略和状态管理一起分析。

## 六、现代密码学与钱包安全的学习地图

| 章节 | 主要建立的能力 |
| --- | --- |
| 一、现代密码学总览 | 知道各类技术解决什么问题，以及它们之间的关系 |
| 二、密码学数学基础 | 理解模运算、有限域、群、多项式与概率 |
| 三、密码学基础构件 | 掌握哈希、随机数、KDF、AEAD、承诺与证明的基本职责 |
| 四、椭圆曲线密码学 | 理解点运算、标量乘法、公钥验证和编码 |
| 五、数字签名算法 | 推导 ECDSA、Schnorr、EdDSA，并辨认实现约束 |
| 六、密钥管理与派生 | 分析密钥生成、派生、备份、恢复与轮换 |
| 七、多方计算与门限密码学基础 | 理解安全模型、秘密共享、VSS、DKG 与份额维护 |
| 八、门限签名协议 | 分析具体协议的消息、计算、校验与失败处理 |
| 九、HSM 与硬件密钥保护 | 理解硬件保护边界及其与 MPC 的组合 |
| 十、钱包签名系统工程 | 分析从业务订单到链上执行的完整信任边界 |
| 十一、密码学攻击与安全实践 | 从攻击条件出发，验证假设并检查防护 |

学习时可以反复沿着“目标—机制—假设—实现”这条主线追问：为什么需要它，它依赖什么，哪些错误会让它失效。

攻击分析也应贯穿学习过程。例如，理解签名随机数的要求时，同时了解复用风险；理解公钥验证时，同时了解非法输入可能造成的影响。

## 七、温习自测

1. 哈希、MAC 和数字签名分别提供什么能力？谁能够生成，谁能够验证？
2. 为什么双方成功完成 ECDH，仍可能无法确认对方身份？
3. AEAD 认证通过、交易签名有效，分别还缺少哪些业务判断？
4. ECC、签名方案、门限协议与 HSM，分别位于什么层次？
5. 阅读一个“安全”的方案时，应当进一步追问哪些攻击条件与假设？
