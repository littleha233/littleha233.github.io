# 本地通用内容发布工作台

## 文章、代码和对话

- **文章 / 随记**：Markdown、纯文本，适合技术记录、生活随笔、阅读笔记等。
- **代码片段**：导入常见代码文件或直接粘贴，填写语言和标题。保留缩进、空行和代码中的 Markdown 围栏，自动生成高亮代码块。不执行代码。
- **对话摘录**：粘贴带“我：”“GPT：”“用户：”“助手：”或 User/Assistant 标记的文本，生成分角色的 Markdown。无法识别角色时保留原文，绝不猜测谁说了什么。
- **JSON 对话导入**：支持 `messages` 数组（每项包含 `role`、文本 `content`），或包含 `mapping` 和 `current_node` 的常见聊天导出结构。先读取目录，再明确选择**一段**对话；只走选中对话的当前分支。不会批量保存或发布整个账号的聊天记录。系统/工具/隐藏消息和非文本附件会跳过并提示。不同导出版本可能不兼容，此时可直接粘贴所需文本。
- `.json` 文件默认进入对话模式；若它是代码或配置文件，可切换“代码片段”。导入原始文件最大 5 MB，单篇正文最大 1 MB。
- 导入对话仅生成草稿，后续可以在 Markdown 中删除不需要的轮次、补充自己的总结，再预览发布。没有连接 GPT 账号，也不主动抓取分享链接。
- 内容类型保存在草稿和导出的 YAML 中，可在内容库筛选。代码与对话发布时自动附带“代码片段”/“对话摘录”标签，Stellar 原有标签页可直接浏览；不改动已有文章分类。
- 可填写来源链接，发布时会出现在正文末尾。链接同样会公开，不应包含私密分享标识、密码或访问令牌。
- 分类建议已扩展到生活、阅读、学习等主题，依然在本机基于关键词给出建议，不调用 AI 服务。

### 对话 JSON 示例

```json
{
  "title": "一次值得记录的讨论",
  "messages": [
    {"role": "user", "content": "怎样把读书笔记写成自己的思考？"},
    {"role": "assistant", "content": "先写出你最不同意的一点，再解释原因。"}
  ]
}
```

隐私检查不能替代人工复核。发布对话前应删去姓名、联系方式、内部资料和未获许可的第三方内容；AI 回复不代表已核实事实。

## 启动

双击项目根目录的 `启动博客工作台.command`，或在项目目录运行 `npm run studio`。
访问 **http://127.0.0.1:4313/**。预览服务使用 4314 端口，仅绑定本机。
Node.js 22+、npm、Git、Python 3 是必需环境，发布还需要 GitHub CLI（`gh`）。
首次依赖安装：`npm ci`。关闭终端停止服务；再次启动即可继续编辑。

## 一篇文章的流程

1. 导入 `.md`，自动读取 YAML front matter，或新建草稿。
2. 输入标题、文章地址、日期（上海时间）、摘要、分类和标签。
3. “提取建议”根据本地关键词和现有博客词库给出分类、标签和摘要，确认后合并，不覆盖手动输入。分类按 Hexo 规则为层级，标签为并列。
4. 添加原文所需图片或 PDF，文件名需要与 Markdown 的相对引用匹配。可点击附件上的“插入正文”。单个最大 10 MB，每篇最多 30 个。
5. 编辑会自动保存；“整理格式”仅规范换行和行尾空格，不改写技术结论或代码，可撤销。
6. “检查并预览”在临时目录构建真实 Stellar 页面，检查原文章、内部链接和附件。断网可用上次同步的主题快照；发布仍必须联网。
7. 检查提交文件清单和完整 Markdown，勾选公开发布确认，点击发布。
8. 等待部署结果，成功后可打开文章、提交记录和 Actions 日志。

## GitHub 登录

在终端自行运行 `gh auth login`，选择 GitHub.com，通过浏览器完成登录。
账号须拥有 `littleha233/littleha233.github.io` 的 Contents 写权限和 Actions 读权限。
CLI 登录通常授予这些能力；如果自行使用细粒度令牌，只选择本仓库及所需权限。
本应用调用 `gh auth token` 在内存中使用已有凭据，不保存、不显示令牌，也不向前端返回。
可兼容启动环境中的 GH_TOKEN / GITHUB_TOKEN；不要将它们写入代码或提交到 Git。
对话中的 GitHub 连接与本机 CLI 登录相互独立。

## 数据和安全边界

- `.blog-studio/drafts/`：本地草稿 JSON 和附件；`.blog-studio/jobs/`：持久化发布记录；均被 Git 忽略。
- 浏览器保留最后未保存编辑作为恢复副本。请勿在不信任的共享 Mac 上写敏感内容。
- 发布前保留草稿快照；已发布内容还可通过 Git 历史恢复。第一版不提供一键删除或回滚公网内容。
- 仅当前文章和附件进入提交；不执行 `git add .`，不上传其他草稿、工作区改动或凭据。
- 发布基于预览时的 main 提交，使用非强制更新。线上已变化、地址重复或草稿已编辑时拒绝发布。
- 内容进入公开 GitHub 仓库，修改或删除文章不等于从 Git 历史中清除秘密。请发布前人工检查。
- 跨源请求、错误 Host、缺少会话校验码的 API 请求均拒绝。预览位于独立源，不能读取编辑器 API。
- 导出文章强制设置 `disableNunjucks: true`，模板语法仅作字面展示。HTML/脚本示例可放在代码块内；正文中的脚本、iframe 等主动内容及不安全链接仍被拒绝。图片/PDF 以受限文件类型导入，检查器不能替代安全审查。
- 六篇历史迁移原稿受原有保真校验保护，只能复制为新稿。本工具发布的新文章可在原草稿中继续编辑并更新。
- 本地源码目录不会在发布后被强制重置；“同步”获取远端文章列表。传统 `localhost:1313` 预览如需同步新文章，请在工作区干净时自行 `git pull --ff-only`。工作台预览始终使用远端快照。

## 验证与故障处理

`npm run test:studio`：导入、标签建议、格式保真、草稿版本、附件、安全边界、隔离构建、模拟 GitHub 发布与冲突测试。
`npm run build && npm run check`：博客整体回归。

- 端口占用：检查已有工作台是否运行，不要重复启动。
- 未登录：运行 `gh auth login` 后点击“检查 GitHub 连接”。
- 断链/缺图：按错误信息补传附件或修改引用，再预览。
- 发布失败：草稿不会丢失。没有产生提交时可修复后重试；有提交 SHA 时先检查记录，不要重复提交。
- 部署失败：查看 Actions 日志；可在 GitHub 修复后重跑，再刷新工作台状态。
- 远端冲突：重新同步和预览；若同一文章由其他工具改动，请另存新地址或人工合并。

实现参考：[Hexo API](https://hexo.io/api/)、[GitHub Git References](https://docs.github.com/en/rest/git/refs)、[GitHub CLI 登录](https://cli.github.com/manual/gh_auth_login)。
